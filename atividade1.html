📱 TEMA 10: Da Web ao Mobile — Estratégias de Apps

Compreenda o mapa das tecnologias modernas de desenvolvimento móvel e aprenda como converter sua aplicação Web (HTML, CSS e JavaScript) em um aplicativo instalável (PWA) e empacotável para Android (APK), inclusive sem instalar Android Studio, direto pelo GitHub.

🌐 Web Apps 📲 PWA ⚡ Capacitor 🐙 GitHub Actions ⚛️ React Native 🎯 Flutter 🤖 Kotlin

🗺️ 1. O Mapa Tecnológico: Como os Aplicativos São Criados?

💡 A Pergunta Essencial: em vez de memorizar códigos de 4 ferramentas diferentes, o bom desenvolvedor aprende a responder: "Qual é a melhor tecnologia para o problema, o prazo e a equipe que eu tenho hoje?"

O mercado de desenvolvimento de aplicativos organiza-se em quatro grandes categorias de acordo com a proximidade do hardware e a linguagem utilizada:

1. Nativo Puro

🤖 Kotlin (Android) / Swift (iOS)

Linguagem oficial do sistema. Acesso 100% irrestrito aos sensores e máximo desempenho gráfico. Desvantagem: código separado para cada loja.

2. Multiplataforma

⚛️ React Native / 🎯 Flutter

Gera apps para Android e iOS a partir de uma única base de código. React Native usa JavaScript/React; Flutter usa Dart.

3. Progressive Web App

📲 PWA (HTML + CSS + JS)

Um site moderno que pode ser instalado na tela inicial do celular pelo navegador, funcionando em tela cheia e offline.

4. Empacotador Híbrido

⚡ Capacitor / Cordova

Pega a aplicação Web existente e a embrulha dentro de um container nativo (WebView), gerando um arquivo .apk.

⚖️ Comparativo Direto das Abordagens

Tecnologia Linguagem Base Plataformas Curva para quem sabe JS Cenário Ideal
PWA HTML / CSS / JS Android, iOS, PC, Mac ⭐⭐⭐⭐⭐ (Imediata) Sistemas internos e CRUDs sem loja.
Capacitor HTML / CSS / JS Android e iOS (APK/IPA) ⭐⭐⭐⭐ (Muito rápida) Levar um sistema Web existente para as lojas.
React Native JavaScript / React Android e iOS ⭐⭐⭐ (Média) Apps comerciais com equipe Web.
Flutter Dart Android, iOS, Web, Desktop ⭐⭐ (Nova sintaxe) Apps com animações refinadas.
Kotlin Kotlin Android puro ⭐ (Ecossistema JVM) Controle fino de hardware.

🚀 2. A Trilha Estratégica: Da Web ao APK

Se a turma já domina HTML, CSS, JS e LocalStorage, o caminho mais produtivo não é começar do zero com nova linguagem, mas evoluir em degraus:

Página Web
(HTML + CSS)
→
App Web
(CRUD + LocalStorage)
→
PWA Instalável
(manifest + sw.js)
→
Empacotamento
(Capacitor no GitHub)
→
App Nativo
(Arquivo .APK)
🧩 O Que Torna um Site uma PWA?
Apenas 3 requisitos fundamentais:
  1. Design Responsivo: a tela se adapta ao tamanho dos smartphones.
  2. Manifesto (manifest.json): nome, ícones, cor da barra de status.
  3. Service Worker (sw.js): cache offline e instalação segura.
  4. HTTPS: exigência do navegador para habilitar a instalação.

🧪 3. Laboratório Prático: Transformando o CRUD em App

Página principal do app. Note o <meta viewport> (adapta ao celular), o <link rel="manifest"> (habilita a PWA) e o <link rel="icon">.

🐙 4. Gerando o APK sem Android Studio: GitHub Actions

💡 Novidade importante: hoje é possível gerar o APK direto pelo navegador, sem instalar Node.js, Android Studio nem configurar SDK local. O GitHub Actions é um serviço gratuito que roda os comandos do Capacitor em servidores na nuvem e devolve o APK pronto para download.

📁 Estrutura do Repositório

seu-repo/
├── .github/
│   └── workflows/
│       └── build.yml       ← gera o APK na nuvem
└── www/
    ├── index.html
    ├── style.css
    ├── app.js
    ├── manifest.json
    ├── sw.js
    └── icons/
        ├── icon-192.png
        └── icon-512.png

🔄 O que o workflow faz

  1. A cada push em main: publica www/ no GitHub Pages (link HTTPS público, com PWA instalável).
  2. A cada tag v*: instala Capacitor, compila o APK e anexa numa Release do GitHub.
  3. Você baixa o APK por github.com/SEU-USUARIO/SEU-REPO/releases/download/v1.0.0/app-debug.apk — link HTTPS que o Chrome não bloqueia.
✅ Zero instalação local. Todo o build acontece nos servidores do GitHub. O aluno só precisa do navegador.
⚠️ Requisito: antes de rodar, é obrigatório ativar em Settings → Pages → Source: GitHub Actions. Sem isso, o job deploy-pwa falha com Get Pages site failed.

⚡ 5. Alternativa: Capacitor Instalado Localmente

💡 Quando usar: se a rede da escola permitir instalar Node.js e Android Studio no computador, o processo local também funciona. É o mesmo que o GitHub Actions faz nos bastidores, mas rodando na sua máquina.

Para o desenvolvedor Web, o fluxo de geração de um APK local torna-se:

// 1. Inicializa o Capacitor no projeto existente
npm install @capacitor/core @capacitor/cli
npx cap init "AlunosApp" "com.escola.alunosapp" --web-dir www

// 2. Adiciona a plataforma Android
npm install @capacitor/android
npx cap add android

// 3. Copia o HTML/CSS/JS e abre no Android Studio
npx cap copy
npx cap open android
🛡️ Vantagem estrutural: o LocalStorage, o CRUD e toda a lógica JavaScript continuam funcionando idênticos no celular, mas agora com ícone na gaveta de aplicativos.
